# v0.4.0 — durable transaction and recovery foundation

**Status:** released on 2026-09-04  
**Claim class:** Experimental

## Goal

Prove that Linura can carry the exact v0.3 reviewed authority subject and authoritative-observation binding across process restart into a durable prepare/pre-dispatch/recovery/verified-commit record **without granting execution authority or performing a supported managed external effect**.

v0.4 closes the authority-to-durability, handoff-freshness, crash, migration, capacity and recovery-concurrency boundaries required before the isolated privileged-executor/verifier qualification in v0.5.

## Released capability contract

v0.4 establishes all of the following within the bounded local SQLite/WAL and filesystem assumptions recorded by the frozen release contract and qualification dossier:

1. A persistence-neutral durable transaction domain owns stable transaction identity, immutable generation identity/bindings, state transitions and typed recovery outcomes.
2. A SQLite/WAL adapter provides explicit application/schema identity, immutable migrations, migration-ledger checksum validation, foreign keys, `synchronous=FULL`, corruption checks and fail-closed open semantics.
3. Durable request idempotency is scoped by authenticated principal plus request ID and survives database/process reopen within one monotonic authority-database history.
4. Ordinary same-key/same-binding replay returns the existing current `Prepared` generation; changed binding is a conflict rather than silent rebinding.
5. Recovery generations are append-only. Prior generation bindings are immutable and a new generation can be appended only through the explicit Control-owned no-effect recovery path.
6. `Verified`, `RecoveryBlocked`, no-effect next-generation append and durable ambiguous-observation handling serialize on the same expected current-generation/state-version boundary.
7. `linura-control` derives durable prepare material only from trusted canonical plan review, authenticated principal, current policy/risk provenance, complete authoritative observation and any required approval.
8. Handoff authority is freshly revalidated immediately before the pre-dispatch transition; observation, policy, risk provenance, principal and approval freshness/revocation are rechecked under the authority-use serialization boundary.
9. Only the single caller that wins the exact `Prepared` → `Indeterminate` CAS may receive the process-local dispatch permit.
10. The dispatch permit is sealed, generation-bound, non-cloneable, non-serializable, non-persistable and non-reconstructible after restart.
11. Restart never recreates execution authority. A lost permit leaves the durable generation `Indeterminate` and requires fresh authoritative re-observation and recovery classification.
12. Authoritative no-effect evidence can enable a newly authorized generation; it never turns the old generation into retry authority.
13. Authoritative intended-state evidence can verify only the exact current indeterminate generation; contradictory evidence can block only that exact current generation; stale or ambiguous evidence remains indeterminate.
14. Commit is allowed only after verification of the current generation at the expected state version and atomically records verified desired-state/graph/provenance references with audit evidence.
15. Retained transaction and audit history is internally integrity-checked and resource-bounded. v0.4 does not claim detection of a coherent rollback of the entire database/filesystem/VM snapshot without an independently protected monotonic anchor.
16. Real ENOSPC recovery keeps bounded same-filesystem reserve capacity, preserves migration immutability and does not shrink rollback-relevant reserve state before a rollback-capable SQLite transaction commits.

## Trust-boundary invariants

- `linura-control` remains the only authority orchestrator and the only workspace consumer of policy semantics.
- Persistence cannot import policy, D-Bus transports, concrete Linux observers or privileged executors.
- `Prepared`, `Indeterminate`, policy `Allow`, approval evidence, reviewed-plan state, transaction identity, generation identity and audit state are **not execution credentials**.
- Database state never replaces authoritative Linux observation for current machine truth.
- Stale/changed/expired/revoked authority cannot transition to an executable handoff.
- A historical generation cannot later win a contradictory recovery outcome after the stable transaction pointer advances.
- Models and agents remain untrusted proposal sources and cannot construct trusted prepare bindings, recovery evidence or dispatch permits.
- v0.4 contains no privileged executor, Polkit grant, public `apply`/execute/mutate surface or supported external machine effect.

## Explicit non-goals retained by the released claim

- No privileged executor or Polkit integration in the v0.4 product boundary.
- No supported Linura-managed external mutation and no public mutation API.
- No complete eleven-stage managed-mutation lifecycle claim.
- No supported distribution, hardware profile or machine-class claim.
- No durable model/agent authority.
- No transparent coherent database/filesystem/VM-snapshot rollback detection.
- No universal storage-durability guarantee from SQLite `synchronous=FULL` alone.

## Release boundary

The released v0.4.0 claim is an **Experimental durable reviewed-authority transaction and recovery foundation** only. It deliberately stops before executor qualification or supported external mutation. v0.5 may qualify one isolated narrow executor/verifier component; v0.6 remains the first milestone allowed to integrate that component with the complete canonical lifecycle and claim a supported managed external effect.
