# v0.5.0 — first narrow privileged executor and independent verifier

**Status:** released
**Target claim class:** Experimental

## Goal

Qualify Linura's first narrow privileged executor and an independent authoritative verifier against the durable pre-dispatch contract established by v0.4.0, while deliberately stopping before a supported Linura-managed external mutation exists.

v0.5 proves that a privileged effect component can be constrained, correlated to exact prepared authority metadata, dispatched through native system APIs, and independently checked from fresh authoritative observation. It does **not** integrate the full eleven-stage lifecycle and does not expose a public `apply`, `execute`, `mutate`, or equivalent product surface.

The first supported managed external effect remains gated to v0.6.0.

## Dependency

v0.5 depends on the immutable, independently verified v0.4.0 durable transaction/recovery release. v0.4 provides the process-local one-shot pre-dispatch permit and exact transaction/generation/binding identities. v0.5 must not weaken, serialize, persist, recreate, or replace that permit merely to make executor integration easier.

## Qualification slice

The deliberately narrow qualification effect is a **restart of a disposable, v0.5-namespaced systemd service fixture**. Qualification may exercise that effect only on disposable VM infrastructure and only through the executor's qualification-only authorization surface.

This choice is intentionally narrower than the future product domain:

- only `.service` units are accepted;
- the qualification entry point accepts only the dedicated `linura-v05-qualification-*.service` fixture namespace;
- no arbitrary systemd method, unit property mutation, command, shell text, environment injection, file write, package operation, or generic root capability is accepted;
- the executor uses systemd's native D-Bus API;
- independent verification uses a fresh systemd observation and does not consume executor success as truth.

The existing `SetUnitEnabled` and `RestartUnit` typed scaffold may remain for contract evolution, but only the explicitly qualified restart fixture operation may cross the privileged qualification boundary in this milestone.

## Required capabilities

1. `linura-provider-sdk` defines bounded Experimental executor/verifier component contracts that preserve provider/resource/effect identity and exact dispatch-correlation material without turning those values into authority credentials.
2. The execution binding carries the exact transaction identity, generation, durable state version, durable authority-binding digest, authority-use digest, effect digest, provider, resource, and operation identity required for future v0.6 integration.
3. The execution binding is deterministic, length-bounded, structurally validated, and domain-separated. Changed resource, operation, generation, authority binding, authority-use identity, or effect material changes the derived effect/dispatch identity.
4. The component contract explicitly states that IDs, digests, plan data, reviewed authority, policy `Allow`, approval evidence, a durable `Indeterminate` row, or executor binding metadata are not independently sufficient authorization.
5. `linura-executor-systemd` runs as a separately hardened root system service on the system bus and exposes only a narrow typed qualification method.
6. The executor authenticates the D-Bus sender and performs an explicit Polkit authorization check for the qualification action before touching systemd.
7. The executor revalidates the complete unit name and qualification namespace at the privilege boundary even when upstream code already validated it.
8. The executor validates exact effect/binding correlation before dispatch and fails closed on malformed, substituted, oversized, or mismatched material.
9. The executor performs the restart through `org.freedesktop.systemd1.Manager.RestartUnit`; it never invokes a shell or accepts arbitrary command text.
10. The executor returns a structured outcome distinguishing rejection before dispatch, successful dispatch acknowledgement, and an indeterminate dispatch outcome where an external effect may have occurred but the caller cannot safely infer final state.
11. Provider errors after the external-dispatch ambiguity boundary are conservatively classified as indeterminate unless absence of dispatch is provable.
12. Executor result text is bounded and sanitized; no untrusted D-Bus/systemd detail becomes an unbounded log/audit payload.
13. `linura-linux-observation` extends authoritative systemd observation with the native monotonic activation timestamp needed to independently distinguish a successful restart from an unchanged active unit.
14. A systemd restart verifier consumes only an expected postcondition plus a fresh canonical `ObservationEnvelope`. It validates exact provider/resource/capability identity, native observation authority, freshness, unit identity, load state, active state, and a strictly advanced activation timestamp.
15. The verifier never imports, links to, calls, or trusts `linura-executor-systemd` and never treats an executor receipt as state proof.
16. Verification outcomes distinguish satisfied, not-satisfied, and inconclusive evidence. Missing/malformed/stale/future/wrong-resource/wrong-provider evidence is never promoted to success.
17. Disposable VM qualification proves success using a dedicated fixture: authoritative pre-observation, privileged restart dispatch, authoritative post-observation, and independent postcondition verification.
18. VM qualification proves fail-closed invalid-unit, wrong-namespace, malformed-binding, effect-substitution, unauthorized-caller, nonexistent-fixture/provider-error, stale-evidence, verifier-mismatch, and ambiguous/indeterminate paths where deterministically injectable.
19. Unit/integration tests cover canonical binding/digest determinism, hostile input bounds, unit-name edge cases, replay/substitution resistance at the component boundary, outcome classification, and verifier independence.
20. The systemd unit is hardened with a minimal system-service sandbox appropriate to a D-Bus-only root executor, including no new privileges, read-only system protection, home isolation, native syscall architecture, restricted address families, and no unnecessary writable filesystem access.
21. Polkit policy is explicit, deny-by-default for ordinary callers, and qualification-scoped. No broad `org.linura.*` wildcard authority is introduced.
22. Repository layering keeps `linura-control`, policy, planner, persistence, public SDK/CLI, agent runtime, and concrete observation implementations out of the executor dependency graph.
23. `linura-control` does not gain an executor dependency in v0.5. The one-shot v0.4 `DispatchPermit` remains process-local and non-serializable; the authenticated handoff mechanism that consumes it and reaches the qualified executor belongs to v0.6 integration.
24. No public D-Bus Control1, `linuractl`, `linura-sdk`, agent, First Boot, or Control Center mutation method is added.
25. Release/roadmap checks pin `executor_state = "isolated-qualified"`, `managed_mutation_support = "none"`, and `complete_lifecycle = false` for v0.5.

## Exact-binding interpretation

v0.5 qualifies the **shape and integrity of the executor-side binding**, not a second source of execution authority.

The component binding is future handoff material: it makes the requested effect unambiguously refer to one transaction generation, one durable binding, one authority-use event, one provider/resource, and one typed operation. The executor validates that exact correlation and the privilege boundary validates the authenticated caller/Polkit action.

Because v0.5 intentionally does not integrate `linura-control` with the executor, the binding itself must remain documented and tested as **non-authoritative metadata**. v0.6 must connect the existing non-reconstructible `DispatchPermit` to the executor over an authenticated one-shot handoff without converting durable rows or caller-supplied digests into reusable credentials.

This separation prevents an attractive but unsafe shortcut where v0.5 would make serialized plan IDs/digests act like bearer tokens.

## Trust-boundary invariants

- The executor is a narrow effector, not a second control plane.
- The executor cannot import planner, policy, approval, Control1, persistence, agent, public SDK, or concrete observation orchestration.
- Polkit authorizes the authenticated qualification caller; it does not validate plan semantics and does not replace Linura's policy/approval/durable authority model.
- The executor binding is correlation/integrity material, not bearer authority.
- A systemd D-Bus acknowledgement proves only that the dispatch call was accepted; it does not prove the intended machine state.
- Verification is based on fresh native authoritative observation obtained independently of the executor.
- Verification code cannot depend on the executor crate or executor-returned state.
- Unknown state, stale evidence, wrong resource/provider/capability, missing attributes, non-native authority, timeout, and ambiguous transport outcomes fail closed.
- No generic privileged shell, process runner, arbitrary systemd method gateway, file-write primitive, or unbounded unit namespace may be introduced.
- Qualification infrastructure may create/destroy the dedicated fixture, but fixture setup is test infrastructure and not a Linura product mutation path.
- The v0.4 durable `DispatchPermit` remains non-cloneable, non-serializable, non-persistable, and non-reconstructible.
- Models/agents remain proposal-only and cannot invoke or acquire the executor qualification action.
- Remote/fleet/model/hosted services remain irrelevant to local executor qualification.

## Required implementation scope

- Add an executor/verifier component contract to `linura-provider-sdk` with bounded identifiers, exact correlation material, deterministic effect identity, structured execution disposition, and structured verification outcome.
- Replace the `linura-executor-systemd` bootstrap binary with a system-bus D-Bus service using native systemd D-Bus and explicit Polkit authorization.
- Preserve strict `UnitName` validation and add a stricter qualification-fixture namespace guard.
- Add a qualification-only restart request/response contract and conservative ambiguity classification.
- Extend systemd authoritative observation with `ActiveEnterTimestampMonotonic`.
- Add an independent systemd restart postcondition verifier under the Linux observation side of the architecture, with no executor dependency.
- Add a dedicated Polkit policy and harden the executor systemd unit.
- Add a disposable v0.5 executor/verifier VM workflow with a dedicated long-running fixture service and bounded polling/deadline behavior.
- Add repository/tooling checks that prevent accidental public mutation integration, generic executor authority, missing Polkit policy, and loss of verifier independence.
- Update threat-model/security/control-plane/provider documentation for the new component boundary.
- Freeze `docs/releases/v0.5.0.md` and qualification evidence only after exact-head review and acceptance are complete.

## Required acceptance evidence

- Exact-source CI, Security and CodeQL success.
- Strict workspace `fmt`, `clippy -D warnings`, tests, repository checks, and `cargo xtask check` success.
- Executor unit tests prove malformed unit names, path traversal, whitespace/control characters, unsupported unit types, wrong fixture namespace, oversized values, malformed digests, and effect substitution fail before dispatch.
- Binding tests prove every material correlation field affects the deterministic dispatch identity and that unknown/extra generic command text cannot be represented.
- Polkit tests/VM evidence prove an unauthorized non-root/non-authorized caller cannot invoke the qualification action while the authorized disposable qualification principal can.
- VM evidence proves the executor uses native systemd D-Bus to restart only the dedicated fixture service.
- Independent verifier tests prove executor `Dispatched` is insufficient by itself and only fresh matching native observation with advanced activation timestamp satisfies the postcondition.
- Stale/future/wrong-resource/wrong-capability/non-native/missing-attribute/unchanged-timestamp observations do not verify.
- Failure evidence covers nonexistent fixture and provider/transport errors without falsely claiming no effect after an ambiguous dispatch failure.
- Timeout/indeterminate evidence demonstrates that uncertain external outcomes require authoritative observation rather than blind retry.
- Layering tests prove no executor dependency enters `linura-control`, public SDK/CLI, agent runtime, planner, policy, transaction, or persistence.
- Static repository checks reject a generic command/shell endpoint or public mutation surface.
- The exact final head receives a fresh adversarial authority/security review after all permanent automated evidence is green; all actionable findings are resolved before release preparation.
- Trusted Release Proof reruns the v0.5 disposable executor/verifier qualification on the exact release candidate before sealed build/promotion.

## Explicit non-goals

- No supported Linura-managed external mutation.
- No public `apply`, `execute`, `mutate`, `restart`, `enable`, or other mutation method in Control1, `linuractl`, `linura-sdk`, agent APIs, First Boot, or Control Center.
- No `linura-control -> linura-executor-systemd` integration; that is v0.6 work.
- No serialization or persistence of `DispatchPermit`.
- No use of plan IDs, digests, transaction rows, approval evidence, or Polkit alone as product execution authority.
- No complete execute → verify → commit → audit → reconcile orchestration.
- No generic systemd proxy and no arbitrary D-Bus method forwarding.
- No package, network, storage, firewall, user, boot, container, VM, or other domain mutation.
- No supported distribution/machine/platform profile claim.
- No agent/model execution authority.
- No fleet/remote execution authority.

## Release handoff

A completed v0.5.0 may claim an **Experimental isolated narrow privileged executor and independent verifier qualification** for the exact disposable systemd fixture scope.

It may claim that the executor is typed, least-privilege, Polkit-gated, native-D-Bus based, exact-effect-bound, hardened, and conservatively ambiguity-aware; and that an independent verifier can prove the fixture restart from fresh authoritative systemd observation without trusting executor self-report.

It must explicitly state that these components are not yet a supported Linura-managed mutation path. v0.6 receives the qualified components plus the v0.4 durable one-shot handoff contract and must integrate them through the complete canonical lifecycle before any supported external effect is published.
