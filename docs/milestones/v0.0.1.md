# v0.0.1 — authoritative observation and causal graph

**Status:** planned
**Target claim class:** Experimental

## Goal

Prove that Linura can authenticate a local caller, obtain authoritative read-only Linux state through provider contracts, represent that evidence in the system graph, and expose it through deterministic non-privileged clients.

This milestone moves Linura from architecture/bootstrap to its first real machine observation. It intentionally performs no privileged mutation.

## Required capabilities

1. Session D-Bus service boundary for `org.linura.Control1`.
2. Caller credentials bound to a typed `Actor`; caller identity cannot be supplied as an unauthenticated client claim.
3. Provider registry/capability discovery with explicit unavailable/degraded states.
4. Read-only systemd observation through the native systemd interface.
5. Read-only NetworkManager observation through the native NetworkManager interface.
6. Observation envelopes with provider identity, resource identity, freshness and authority semantics.
7. Population of observed resource/capability nodes and evidence edges in the system graph.
8. `linuractl observe`, `graph`, `capabilities` and evidence-only `explain` operations over the public SDK/protocol boundary.

## Trust-boundary invariants

- `linurad` remains unprivileged.
- No generic shell or privileged executor is introduced.
- Provider observation is authoritative for current machine state; persisted or client-supplied state cannot override it.
- Unknown, stale, malformed or mismatched observations are explicit and cannot be promoted to trusted current state.
- D-Bus caller identity is derived from the transport/OS boundary.
- An AI/model provider is not required for any v0.0.1 capability.
- Read-only observation must not create an implicit mutation authority path.

## Implementation scope

- D-Bus transport skeleton and caller-credential extraction.
- Provider registry and health/support reporting.
- systemd and NetworkManager observer implementations.
- Observation freshness/identity validation.
- System-graph population from observed evidence.
- Deterministic CLI/SDK query surfaces.
- Unit, contract, integration and disposable-VM observation fixtures.

## Required acceptance evidence

- Canonical Rust formatting, clippy and workspace tests on exact source.
- Repository/tooling checks and CodeQL/Security gates.
- Negative tests for caller-identity spoofing, provider/resource mismatch, malformed observation and stale evidence.
- Disposable VM acceptance proving systemd observation against known units.
- Disposable VM acceptance proving NetworkManager observation where the test image exposes the service.
- Repeat-observation tests proving changes outside Linura are reflected by subsequent authoritative reads.
- No privileged code path required to pass the milestone.

## Explicit non-goals

v0.0.1 does not:

- execute system mutations;
- introduce Polkit or a privileged executor;
- persist desired state or durable prepare/commit transactions;
- claim a supported desktop or hardware configuration;
- use an LLM to interpret intent;
- implement First Boot configuration;
- claim production readiness.

## Exit criteria

- [ ] All required read-only capabilities are implemented through the public control/protocol boundaries.
- [ ] Caller identity is authenticated and tested against spoofing.
- [ ] systemd and NetworkManager observations have explicit freshness/authority semantics.
- [ ] Observed evidence populates/queryable system graph state.
- [ ] Disposable VM acceptance proves representative observation and out-of-band change visibility.
- [ ] Exact-source CI, Security and CodeQL are green.
- [ ] Known limitations/unsupported observation states are documented.
- [ ] `docs/releases/v0.0.1.md` is frozen with PR/commit traceability before tagging.

## Release handoff

The v0.0.1 release contract may claim **Experimental authoritative read-only observation** only for the providers and VM/profile evidence actually proven. It must explicitly state that no privileged managed mutation is supported.
