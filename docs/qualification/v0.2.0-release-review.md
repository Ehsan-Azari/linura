# v0.2.0 release-preparation review record

This supplemental review record documents a release-engineering defect discovered while reviewing the v0.2.0 preparation candidate. It does not replace `docs/qualification/v0.2.0.md` or machine-generated CI/VM evidence.

## Duplicate VM artifact identity

**Discovered in:** release-preparation PR #39 review.

**Problem:** Trusted Release Proof was changed to invoke the reusable disposable-VM workflow twice in the same workflow run—once for `authoritative-observation` and once for `control1-plan-preview`—but the reusable workflow named both uploaded artifacts only from the source SHA. GitHub Actions artifact names must be unique within a workflow run, so the second upload could collide and block the proof chain even when both VM scenarios themselves passed.

**Root correction:** VM evidence artifact identity now includes both the acceptance scenario and exact source SHA. The reusable VM job and scenario-execution step were also renamed to scenario-neutral labels so audit output does not mislabel a Control1 plan-preview run as authoritative-observation-only evidence.

**Regression protection:** repository tooling asserts that the scenario-scoped artifact pattern exists, that the old scenario-independent artifact name is absent, and that Trusted Release Proof still requires both mandatory v0.2.0 VM jobs before build/promotion.

**Decision:** this defect is release-blocking until the corrected exact head passes canonical CI, Security, CodeQL, both disposable-VM gates, and a fresh post-fix review. Historical green results from the pre-fix source cannot waive those requirements.
