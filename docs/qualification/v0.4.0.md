5. **PR #62** — deterministic pre-open ENOSPC terminal recovery, immutable V1→V2 migration, custom-limit recovery, literal migration pins, and commit-ordered reserve release for both single- and multi-reservation rollback. Final exact head `8ebf8e3c3b861f222c228c379ea21478e296b205`; protected-main squash merge `072ca08c92a8e146aab49ded8a7f94bf646394d6`.

PR #62 closes the real blocker exposed by Trusted Release Proof after PR #61: at genuine filesystem ENOSPC a new process could fail while reopening SQLite before the transaction-level reservation-release trigger became reachable. The final design releases only the dedicated opener slot **before** SQLite open using bounded Linux hole punching while preserving logical sidecar length, restricts that special open to terminal Prepared retirement, and makes every reservation `DELETE` filesystem-neutral until SQLite commit. Physical reserve shrinking is performed only afterward through authenticated, write-serialized reconciliation.

The additive SQLite migration is explicit and immutable: historical `MIGRATION_V1` remains unchanged; `MIGRATION_V2` replaces the legacy release trigger; schema-v1 stores are authenticated before migration; the migration ledger is exact and bounded; and CI pins literal SHA-256 digests of released migration bodies so an assigned migration ID cannot silently drift with runtime checksum code.

## Trust and authority interpretation

v0.4 proves a durable **authority transaction/recovery substrate**, not managed mutation support. `Prepared`, `Indeterminate`, `Verified`, committed metadata, policy `Allow`, approval evidence, transaction/generation identity and a process-local dispatch permit are not public mutation credentials. The repository remains at:

- `executor_state = "none"`;
- `managed_mutation_support = "none"`;
- `complete_lifecycle = false`.

Raw filesystem/database writers can alter bytes, but they cannot mint valid keyed retained-record integrity tags without the separately provisioned integrity key. Coherent rollback of the whole database/filesystem/VM snapshot remains explicitly unsupported without a future independently protected monotonic anchor/restore protocol.
