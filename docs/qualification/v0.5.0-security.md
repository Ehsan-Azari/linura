# v0.5 isolated executor/verifier security boundary

**Milestone:** v0.5.0  
**Claim:** Experimental qualification only  
**Managed mutation support:** none  
**Complete lifecycle:** false

This document is the focused security contract for the first privileged Linura component. It supplements `docs/threat-model.md`, `docs/security-model.md`, ADR 0021 and the v0.5 milestone; it does not create a supported public mutation path.

## Assets and trust decisions

The high-value assets are:

- operating-system privilege reachable through the root executor's systemd D-Bus connection;
- authenticated system-bus caller identity;
- the Polkit authorization decision for the qualification action;
- exact transaction/generation/effect/dispatch correlation material;
- canonical authoritative systemd observation;
- the separation between dispatch acknowledgement and postcondition proof.

The executor is trusted only to validate and dispatch the fixed qualification effect. It is **not** trusted to establish caller authority by itself, to synthesize current machine truth, to widen policy, to reconstruct v0.4 dispatch authority, or to claim a completed lifecycle.

The verifier is trusted only to evaluate a postcondition over an already-produced canonical `ObservationEnvelope`. It does not own transport or privilege.

## Threats and required controls

| Threat | Required control | Permanent evidence |
| --- | --- | --- |
| Caller identity spoofing | Read unique sender from the authenticated system D-Bus header; never accept principal/caller as payload | executor unit tests + ordinary-caller VM denial |
| Polkit bypass or broad grant | Fixed action ID; production policy defaults `no/no/auth_admin`; test grant is under `tests/` only | policy anti-drift test + VM authorized/unauthorized paths |
| Arbitrary root command execution | No generic command API; effect is fixed native systemd `RestartUnit`; only fixed `/usr/bin/pkcheck` helper | static boundary test + source review |
| Systemd method or unit substitution | Strict `linura-v05-qualification-*.service` parser and fixed `restart-unit` effect descriptor | wrong-namespace/effect-substitution VM paths |
| Digest/binding values treated as bearer authority | OS caller authentication and Polkit remain mandatory independently of deterministic binding validation | architecture contract + unauthorized call with otherwise-valid binding |
| Malformed or substituted binding | Parse fixed-width component digests and re-derive/validate the exact effect/dispatch binding before dispatch | malformed and substitution VM paths |
| Provider ambiguity after a failed native call | Native `RestartUnit` error after dispatch attempt is `indeterminate`, never silently safe-to-retry | nonexistent fixture VM path |
| Executor self-attestation | `dispatched` means acknowledgement only; no executor receipt can satisfy verification | pure verifier dependency/source contract + VM proof from canonical observation |
| Stale/replayed observation | Exact provider/resource/capability plus `NativeApi` authority and freshness-window validation | verifier tests + stale VM path |
| False restart proof | Require loaded/active state and `ActiveEnterTimestampMonotonic` strictly greater than the pre-dispatch baseline | canonical observer + positive/unchanged VM paths |
| Verifier/observer implementation drift | Verifier has no `zbus`, executor or concrete Linux-observer dependency; canonical observer owns native systemd state | tooling anti-drift test |
| Privilege expansion through service configuration | Root-owned dedicated service, strict filesystem/home/device/namespace restrictions, AF_UNIX only, empty capability and ambient capability sets | tracked unit + VM `systemctl show` evidence |
| Qualification grant ships as product policy | VM-only principal rule remains under `tests/acceptance/v05`; production Polkit XML contains no qualifier principal | tooling anti-drift test |
| Accidental public mutation surface | No executor imports from apps/public SDK/control/protocol paths in v0.5 | tooling anti-drift test + layering contract |
| Qualification evidence detached from source | exact source checkout, pinned VM image digest, pinned toolchain, artifact hashes and permanent release-proof dependency | v0.5 qualification workflow + Trusted Release Proof |

## Authorization flow

1. A process sends the fixed `QualifyRestart` call on the system bus.
2. D-Bus supplies the authenticated unique sender name in the message header.
3. The executor asks `/usr/bin/pkcheck` to evaluate the fixed qualification action for that system-bus name.
4. Only after authorization does the executor parse the qualification unit and binding.
5. The executor re-derives the canonical restart effect and validates the supplied binding against it.
6. The executor invokes systemd's native `RestartUnit(unit, "replace")` method.
7. A successful method return is only `dispatched`; failure whose external effect cannot be proven is `indeterminate`.
8. Canonical Linura observation independently reads current systemd state.
9. The pure verifier evaluates the expected restart postcondition against that observation.

No transaction digest, approval record, policy result, reviewed plan, executor return value or agent/model output skips steps 2–5 or substitutes for steps 8–9.

## Service-hardening interpretation

The executor intentionally runs as root because the qualification is about a real privileged boundary. The service unit nevertheless removes unnecessary ambient mechanisms: `NoNewPrivileges`, strict filesystem protection, protected home, private devices/tmp, namespace restrictions, native syscall architecture, system-service syscall filter, AF_UNIX-only networking, and empty Linux capability/ambient-capability sets.

Those settings reduce exploit surface but do not make compromise harmless. A root process with access to systemd's system-bus API remains high consequence. The primary safety property therefore remains **semantic narrowness plus OS authorization plus independent verification**, not sandbox flags alone.

## Explicitly out of scope for v0.5

- connecting this executor to v0.4's sealed dispatch permit;
- public CLI/SDK/protocol `apply`, `execute` or `mutate` operations;
- package/file/network/user/service configuration beyond the single disposable restart fixture;
- production authorization UX or policy distribution for managed mutation;
- retry/recovery integration after an indeterminate external effect;
- claiming an eleven-stage or otherwise complete managed-mutation lifecycle;
- general distribution/hardware qualification.

Those are integration work for v0.6 or later and require a new security review rather than inheriting authority from this qualification milestone.
