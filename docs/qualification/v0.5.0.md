## Claim-to-evidence map

| Claim | Positive evidence | Negative/failure evidence |
| --- | --- | --- |
| Executor privilege is narrow | fixed systemd `RestartUnit`, fixed action ID, strict fixture namespace | wrong namespace, malformed binding and effect substitution rejected before dispatch |
| Caller identity is OS-authenticated | unique sender from system D-Bus header plus Polkit | ordinary unprivileged caller denied |
| Binding is exact but non-authoritative | deterministic full-field effect/dispatch validation | changed effect/resource/binding fails; valid binding alone cannot bypass Polkit |
| No generic root command surface | native systemd proxy, fixed `/usr/bin/pkcheck`, static anti-drift checks | shell/generic command markers prohibited |
| Dispatch acknowledgement is not state proof | post-observation uses canonical native observer | verifier has no executor or zbus dependency and cannot consume executor receipt |
| Restart proof is authoritative | fresh `NativeApi` envelope, loaded/active state, advanced `ActiveEnterTimestampMonotonic` | stale evidence inconclusive; unchanged timestamp not satisfied; mismatches fail closed |
| Provider ambiguity is conservative | dispatch errors become `Indeterminate` | nonexistent fixture path proves no false safe-to-retry claim |
| Privileged waits are bounded | five-second zbus connection method timeout | synthetic timed-out native method error remains `Indeterminate` and bounded |
| Production authorization remains narrow | production policy `no/no/auth_admin` | qualification-only principal rule exists only under `tests/acceptance/v05` |
| Service is hardened | `NoNewPrivileges`, strict filesystem/home/device/namespace/network/capability restrictions | anti-drift tests and VM `systemctl show` evidence |
| v0.5 does not become product mutation | layering + public-surface anti-drift tests | no Control1/CLI/SDK/agent executor method and no control→executor dependency |

## Security/authority review closure

Fresh exact-source review treated the executor as a high-consequence root boundary rather than accepting green tests alone. The review covered authenticated caller identity, Polkit semantics, namespace parsing, exact effect substitution, digest/binding authority confusion, shell/command injection, result bounds, D-Bus/systemd ambiguity, verifier independence, stale/future observation, service hardening, qualification-policy leakage, public-surface leakage, layering, and proof-source attachment.

One valid gap remained after the initial implementation: the native method call had no explicit bounded reply deadline even though timeout/indeterminate behavior was part of the milestone contract. PR #69 fixed that gap and added permanent regression. Corrected exact-head CI/Security/CodeQL and the complete disposable VM then passed. No other actionable v0.5 authority/security finding remains open for the bounded claim.

## Qualification environment

The permanent v0.5 workflow uses a repository-pinned Ubuntu 24.04 LTS amd64 cloud image URL and SHA-256 digest, a pinned Rust toolchain, QEMU with deterministic TCG acceleration, ephemeral cloud-init/SSH identity, and a dedicated `linura-v05-qualification-restart.service` fixture.

The VM proves the real root system service, system bus, Polkit, systemd native API, canonical Linura observer and independent verifier together. Test-only authorization is installed inside the disposable guest and is explicitly excluded from production policy.

## Boundary retained

The release remains:

- `executor_state = "isolated-qualified"`;
- `managed_mutation_support = "none"`;
- `complete_lifecycle = false`;
- no public apply/execute/mutate/restart surface;
- no supported distribution/machine/hardware profile;
- no agent/model execution authority.

The v0.4 one-shot `DispatchPermit` remains process-local, non-serializable, non-persistable and disconnected from the v0.5 executor. Integration belongs to v0.6.
